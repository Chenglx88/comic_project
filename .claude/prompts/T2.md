# T2 条文规范（跨集重构 / 管线改造）

本期只落规范，**不建 `prompt-router`、不建三腿判决账本、不建 `meta.sh`**。待 `07_pipeline/` 代码落地后启用。

## 定档判据

命中任一条即升 T2：

1. 触及 `00_schema/`、角色锁、公共命名、权限或依赖版本
2. 改动 ≥5 个文件，或跨 ≥2 个模块
3. 删除、重命名、移动文件，或跨包重构
4. 不可逆（无版本控制 / 无备份 / 生产副作用）
5. 根因不明，需试错定位
6. 存在多种合理解释或技术方案
7. 需新增依赖
8. 验收无法用单条命令表达

## 三腿映射（本期只定名，不实现 router）

| 腿 | 代理 | 看什么 |
|:--|:--|:--|
| 施工 | 对应生产岗 / `pipeline-coder` | 按条文产出 |
| 复审 | `continuity-auditor` / `pipeline-reviewer` | 范围、契约、安全 |
| 对抗 | `pipeline-tester` / `episode-gate` | 从零复算判据 |

## 纪律

- 三条腿缺一不可；缺腿不得报「全部完成」。
- 审查必须独立，禁止产出者自查。
- 判决必须落盘；只回传不留痕不算完成。
- 「本轮不可判」不得记成 `DONE`；给不出替代判据就记 `DONE_WITH_CONCERNS`。
- 降档必须用户裁决；执行中命中未覆盖的重型项 → 停下申请升档。
- 命中判据 ②③（删除/搬迁）时，必须给「旧文件清单 ⇄ 行为保真清单」且条数对齐。
